# 变现路径枚举与初筛

## 为什么不能抄现成清单

搜「AI 自动赚钱方式」得到的清单有三个致命问题：

1. **它们本身就是变现产品**——那些文章的作者靠卖课/导流赚钱，清单是获客素材，不是调研结论。
2. **已经被抄烂**——凡是能被搜到的、写成清单的玩法，衰减半衰期通常已经过了。
3. **它们按「做什么」组织，不按「谁付钱」组织**——于是全是「做 SEO 站」「做 GPTs」这种
   缺了付费方的半截答案。

所以：**从四轴生成，不从清单抄。** 搜到的清单只能当作「存在这种玩法」的线索（C 级来源），
必须重新走一遍四轴才能进候选池。

---

## Step 1 · 四轴生成

对每一条候选，**必须同时填满四格**。填不满的不是候选，是半个想法。

| 轴 | 问题 | 举例维度（不是答案清单，是提问方向） |
| --- | --- | --- |
| **谁付钱** | 具体是谁掏钱？企业采购 / 个人消费者 / 平台分成 / 广告主 / 开发者？他的预算从哪个口子出？ | 已经在为这件事花钱的人 > 理论上应该愿意花钱的人 |
| **交付什么** | 交付物是什么形态？一次性产物 / 订阅访问 / API 调用 / 数据 / 撮合结果？ | **能不能零人工交付**是核心 |
| **收款轨道** | 钱怎么到账？个人主体能不能开？两个法域各是什么？ | 这一轴最常杀死候选，见 Step 2 问 2 |
| **获客渠道** | 第一个客户从哪来？流量是买的、搜来的、平台派发的、还是别人推荐的？ | **持续人工运营的渠道 = 持续人工托管** |

**生成方法**（配合全局 skill `first-principles-thinking`）：

- 固定「谁付钱」，遍历另外三轴 → 得到一族候选
- 固定「收款轨道」（例如：平台自带分成、无需自建收款），反推谁付钱 → 另一族
- 固定「获客渠道」（例如：平台自带流量分发，无需买量）→ 又一族

**目标：≥ 20 条候选。** 少于 20 条说明你在抄清单而不是在生成。

### 候选表格式（写入 `research/00-candidates.md`）

```markdown
| # | 候选名 | 谁付钱 | 交付什么 | 收款轨道 | 获客渠道 | 初筛结论 | 淘汰理由 |
|---|--------|--------|----------|----------|----------|----------|----------|
| 1 | ...    | ...    | ...      | ...      | ...      | 进池/淘汰 | ...     |
```

**淘汰理由必须具体到判据**（「问 3 不过：交付需要每单人工审核」），
不许写「感觉不太行」「竞争激烈」。

---

## Step 2 · 五问初筛闸门

**任何一问答「否」= 淘汰。** 不许「加个风险提示后保留」。

### 问 1 · 有没有真实的付费方？

- 有 **A 级证据**证明这类买家已经在为这件事花钱吗？（现有产品的定价页、平台的分成条款、
  公开的采购记录、同类服务的收费标准）
- ❌ 「理论上企业应该愿意为 X 付费」= 否
- ⚠️ 只有 C 级来源（别人说他赚到了）= 否，除非能找到 A 级佐证付费方的存在

### 问 2 · 收款轨道对个人主体开放吗？（最常杀死候选的一问）

**两个法域分别回答，各需 A 级来源：**

- 个人（非公司）能不能开户收款？
- KYC / 实名要求是什么？需要哪些材料？
- 提现门槛、结算周期、费率是多少？
- 有没有地区限制（某些收款服务不向特定法域的个人开放）？

**两个法域都答不出来 = 淘汰。** 一个法域可行、另一个不可行 → 保留，标注「仅 X 法域可行」。

### 问 3 · 交付能否零人工？

- 交付物能不能在没有人参与的情况下产生并送达？
- **有没有「每单都要人看一眼」的环节？**（人工审核、定制沟通、质量把关）
- 如果有，是**每单必须**还是**抽样即可**？抽样可以留，每单必须的淘汰。

### 问 4 · 获客是否依赖持续人工？

- 第一个客户之外，第 100 个客户从哪来？
- 这个渠道需要**持续的人工运营**吗？（每天发内容、每天回私信、每周维护社群）
- **平台自动分发 / 搜索自然流量 / 口碑复购** → 通过
- **需要人设、需要日更、需要社群运营** → 淘汰（那是在给平台打工，不是无人托管）

### 问 5 · 目标平台的 ToS 允许自动化吗？

- 找到目标平台的 ToS / 开发者协议**原文**（A 级）
- 有没有「禁止自动化」「禁止批量」「禁止 AI 生成内容」「限制账号数量」条款？
- **踩到 CLAUDE.md §2.4 红线的直接淘汰**，不进池

**查不到 ToS 原文** = 按 UNKNOWN 处理 = **按最严格情况处理**（`REFERENCE §8.3`）。

---

## Step 3 · 出池

- 通过五问的候选 → **深挖池**，目标 6–8 条
- **多于 8 条**：按「预估 time-to-first-dollar」排序取前 8，其余在候选表里标注「未深挖」
- **少于 6 条**：回 Step 1 换一个固定轴重新生成，不要降低五问标准

📌 **淘汰理由比入选理由更值钱。** 候选表里被淘汰的那 12+ 条，每条的淘汰理由
就是你对这个领域理解的证据。写清楚它们。

---

## 失败处理

| 情况 | 怎么办 |
| --- | --- |
| 生成不出 20 条 | 换固定轴（从「谁付钱」换到「收款轨道」）重新遍历，不要放宽四轴填满的要求 |
| 某条候选的「收款轨道」查不到 A 级来源 | **不许猜**。标注「未查到」→ 该问答否 → 淘汰，并记入 `OPEN-QUESTIONS.md` |
| ToS 原文打不开 / 需要登录 | 先写盘已有内容，再试官方帮助中心 / 开发者文档 / 归档版本。三次都拿不到 → 按 UNKNOWN 处理 |
| 深挖池不足 6 条 | 回 Step 1，**不要降低五问标准凑数** |
| 连续 2 次检索无新增证据 | 触发无进展检测（CLAUDE.md §4）→ 强制换策略 |

## 安全边界

- 本 skill **只做枚举和纸面初筛**。不注册、不测试、不联系任何人、不花钱。
- **不得为了凑够深挖池数量而放宽五问。** 6 条合格候选 > 8 条含水分候选。
- 踩到 CLAUDE.md §2.4 红线的候选，**记录 + 淘汰**，不做「风险提示后保留」。
- 单条候选的初筛检索 ≤ 3 次。要更多就说明它该进深挖池，或者该淘汰。
