# 环境定调

## 顺序：先写自己的，再看平台的

`daily_log.csv` 让人先填 `my_read` 再看 `phase_shown`，理由写在 `记录说明.md`：
*先写你的，再看平台的，别被它带着走*。

本节点同理。**先根据 `limit_up` / `seal_rate` / `ge2_count` / `strong_down_pct` 等原始计数写出
自己的判断，再读 `phase`。** 顺序反了就只是给平台的标签配文案。

两者不一致时**说明分歧点**——这正是 `deviation_from_system` 想记录的东西。

## `state` 与 `phase` 是两套独立标签

| | `state` | `phase` |
|---|---|---|
| 取值 | `strong / lean_strong / neutral / lean_weak / weak` | `ice / ignite / rally / climax / ebb / repair` |
| 算法 | 当日打分，5 档 | EMA(α=1/3) + 两日确认 |
| 切换频率 | **73.7%** 的日子会变（179/243） | 平均段长 **12.20 天**（20 段 / 244 天） |
| 性质 | 当日快照 | **平滑后的同步/滞后标签** |

**关键**：`phase` 因为做了平滑和两日确认，**结构上不可能领先**。段长越长，滞后越严重。把它当次日预测读，
就是 `mean(edge) = −0.134` 抓到的那个陷阱。

正确用法：`phase` 是**背景**（今天处在什么样的环境里），不是**预测**（明天会怎样）。
预测要从原始计数的分位与变化率里找。

## 实测分布对定调的三条约束

完整分布表在规格书 §1.2（244 天实测，唯一权威）。对本步骤有直接后果的是三条：

- **`repair` 占 84.8%**（raw）/ **86.1%**（弱档否决后，即 `scoreboard.load_regime()` 实际评分的口径）。
  `AGENT.md` 记的是 ~74%，两个口径都比它高。**绝大多数夜晚的正确输出是 `无判断`。**
- **`climax` 在这个窗口里一次都没出现过。** 遇到任何关于高潮期的推理，标 `待数据`——
  不是「未通过」，是没样本。
- `ebb`(7 天) 与 `ice`(3 天) 永远达不到 `MIN_BASELINE_SAMPLES = 12`，
  **这两个阶段拿不到 `base_rate`** → 落在它们上面时输出 `无判断`。

## 弱档否决

平台 `docs/market-phase.md` 的规则：`state ∈ {weak, lean_weak}` 时，正向阶段（`ignite`/`rally`/`climax`）
一律降为 `repair`。

`scoreboard.load_regime()` 自己又套了一次这条规则，因为**实测平台落盘的 `phase` 列有 3/244 行
没套用**（原值保留在 `phase_raw`）。

**读 `phase` 时要意识到你读的可能是被否决后的值。** 需要原始标签时看 `phase_raw`。

对应规则：`SPEC-ENV-01`——闸门关闭时当日不产生买入侧研判。

## 市况三分

`SPEC-ENV-02` 用 `above_ma20_pct` 把市况分三档（上涨 / 盘整 / 下跌），对应书房「不同市况，不同选择」：

- **上涨**：选板块内龙头
- **盘整**：选有突破迹象的个股（`SPEC-VOL-09` 放量突破）
- **下跌**：空仓；唯一豁免是 `SPEC-ENV-03`（始终在 `ma10`/`ma20` 之上的最强个股，且快进快出）

**⚠️ 三分的阈值（0.5 / 0.35）是规格书设定的，不是书里的数字，未经标定。**
引用时要说这一点。

## 别用错的字段

- `up_ratio` 是**涨跌家数比**，不是上涨占比。要占比自己算 `up_count / (up_count + down_count)`
- `avg_turnover` 是**成交额**，不是换手率
- `strong_up_pct` / `strong_down_pct` 是 0–100，同表其余多为 0–1

完整台账见 `ashare-short-term-playbook` 的字段语义与缺口台账。
