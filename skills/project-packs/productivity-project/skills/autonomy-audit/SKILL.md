# 无人托管审计（七环节）

## 核心命题

> **大多数「AI 自动赚钱」方案不是死在技术，是死在收款与合规。**

技术上「让 AI 自动生成内容/代码/设计」早就不是瓶颈。真正的瓶颈在：
谁能开这个收款账户、平台允不允许自动化、退款争议谁来处理、封号了怎么恢复。

**这些环节里只要有一个需要人持续在场，整条路径就不是无人托管的**，
不管另外六个环节自动化得多漂亮。

---

## 七环节审计表

对每条深挖候选、**每个法域各填一张**。写入 `research/NN-<候选名>.md`。

```markdown
### 无人托管审计 · [候选名] · [法域：海外美元体系 / 中国大陆]

| # | 环节 | 具体是什么 | 自动化等级 | 持续人工(h/月) | 依据(A级来源+日期) |
|---|------|-----------|-----------|---------------|-------------------|
| 1 | 获客 | | | | |
| 2 | 成交 | | | | |
| 3 | 收款 | | | | |
| 4 | 交付 | | | | |
| 5 | 售后与退款 | | | | |
| 6 | 合规与实名 | | | | |
| 7 | 争议与封号恢复 | | | | |
| | **合计** | | | **X.X h/月** | |

**最脆弱环节**：第 N 环 —— [为什么它最脆弱 / 它坏掉时会怎样 / 多久才会被发现]
**一次性人工设置总量**：约 X 小时（[列出具体项]）
```

### 自动化等级的三档定义（口径必须一致）

| 等级 | 定义 | 计入 h/月 |
| --- | --- | --- |
| **全自动** | 日常运转完全无人参与，异常也有自动兜底 | 0 |
| **一次性人工** | 只在启动阶段需要人（开户、KYC、备案、首次上架、绑卡） | 0（另计入「一次性设置总量」） |
| **持续人工** | 日常需要人反复参与 | 按实际估算填 h/月 |

⚠️ **不许出现「半自动」这种模糊档位。** 分不清就归为持续人工——
`REFERENCE §8.3`：UNKNOWN 按最严格情况处理。

## 逐环节的必答问题

### 1 · 获客

- 第 100 个客户从哪来？渠道是**平台自动分发 / 搜索自然流量 / 口碑复购**，
  还是**需要人日更、维护人设、社群运营**？
- 冷启动期和稳态期的人工量分开估——冷启动的算「一次性」，稳态的算「持续」。
- ⚠️ 最容易低估的一环。「做个自动发布脚本」不等于零人工——
  **内容策略、账号维护、平台规则变化的应对**都是人工。

### 2 · 成交

- 从「潜在客户看到」到「钱进来」中间有几步？有没有需要人回答的问题？
- 有没有议价、定制、方案沟通环节？（有 → 持续人工）
- 有没有需要人工审核买家资质的环节？

### 3 · 收款（最常杀死候选的一环）★

**每一条都需要 A 级来源（官方费率页 / 服务条款原文）：**

- 个人（非公司主体）能不能开户？还是必须有营业执照 / 公司实体？
- **KYC 要求**：需要哪些材料？多久审完？拒了怎么办？
- **地区限制**：本法域的个人能不能用这个收款服务？
- **费率、提现门槛、结算周期**分别是多少？
- **风控冻结**：什么情况下会冻结资金？冻结后解冻流程需要人做什么？

> ⚠️ 「用某某收款服务就行了」不是答案。**要有 A 级来源证明本法域的个人主体能开。**
> 查不到 → 该环节判为**未查到** → 整条候选进 `OPEN-QUESTIONS.md`，不许猜。

### 4 · 交付

- 交付物从生成到送达，有没有**每单必须人看一眼**的环节？
- 质量把关是**每单必须**还是**抽样即可**？（抽样可以留，每单必须的判持续人工）
- 生成失败 / 交付失败时，有没有自动重试与兜底？还是等人发现？
- 交付成本随单量线性上涨吗？（涉及 `unit-economics`）

### 5 · 售后与退款

- 退款是**自动处理**还是**人工审批**？平台代处理还是你自己处理？
- 客户提问怎么办？有没有自助文档 / 自动回复能覆盖 80%？
- 退款率大概多少？（这是 CLAUDE.md §2.5 的**反向指标**之一，必须给数）
- ⚠️ **退款是不可逆的金钱动作**（`REFERENCE §8.3` HIGH 风险）——
  如果这条路径需要你逐笔判断退不退，它就不是无人托管的。

### 6 · 合规与实名

- 需要什么资质？（营业执照、ICP 备案、行业许可、税务登记）
- 税务处理：收入怎么报？需要人每月/每季做什么？
- **年度性的人工**（年检、续期、报税）按 h/12 折算进 h/月。
- 有没有需要真人出面的环节（人脸识别、面签、现场核验）？那是一次性还是周期性？

### 7 · 争议与封号恢复 ★ 最容易被完全忽略的一环

- 账号被封 / 内容被下架的概率有多大？（**反向指标**，必须给判断依据）
- 申诉流程是什么？需要人做什么？平均多久？
- **封号后收入归零的恢复成本**是多少？能不能换个号继续？
  （注意：批量换号踩 CLAUDE.md §2.4 红线 → 直接淘汰）
- 有没有**单点依赖**？整条路径挂在一个平台账号上，那个账号就是最脆弱环节。

---

## 输出：三个必须给的结论

1. **合计人工小时/月** —— 七环节的持续人工加总。这是候选间排序的主要口径。
2. **一次性人工设置总量** —— 单独列，不加进 h/月。
3. **最脆弱环节 + 它坏掉时的后果 + 多久才会被发现** ——
   `REFERENCE §6 测量衰减`：一条路径最危险的失效是「仪表盘全绿但收入已经归零」。

## 失败处理

| 情况 | 怎么办 |
| --- | --- |
| 收款/合规环节查不到 A 级来源 | **fail-closed**：写「未查到」，该环节判持续人工且标记不确定，整条候选记入 `OPEN-QUESTIONS.md` |
| 只查到某一个法域的信息 | 另一个法域写「未查到」，**不许用一个法域的结论推另一个** |
| 某环节分不清是一次性还是持续 | 归为**持续人工**（UNKNOWN 按最严处理） |
| 找不到退款率 / 封号率的数据 | 写「无公开数据」+ 给出你的定性判断**和判断依据**，不要编一个百分比 |
| 连续 2 次检索无新增证据 | 触发无进展检测 → 换法域 / 换语言 / 换源类型，不要换同义词再搜 |
| 单条候选检索超过 12 次 | 撞闸门 → 用现有证据收口，在表里标注「证据不足」 |

## 安全边界

- **只做纸面审计。** 不注册账号验证 KYC 流程、不提交任何表单、不测试任何收款服务。
- **不得为了让某条候选的 h/月 看起来更低而放宽档位定义。**
  分档口径是冻结节点（CLAUDE.md §2）。
- 发现某条路径必须靠**批量账号 / 绕过实名 / 绕过风控**才能自动化 →
  踩 §2.4 红线 → **淘汰，不做「风险提示后保留」**。
- 「h/月」的每个数字都要能说出怎么算的。**拍脑袋给一个总数不算数。**
