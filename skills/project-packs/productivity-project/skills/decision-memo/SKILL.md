# 决策备忘录

## 前置：打分必须在干净上下文里做 ★

`REFERENCE §3.3 / §4 类别三`：**verifier 和 generator 共享上下文，它会给自己盖章。**

所以 Phase 4 打分是一个**独立 pass**：

- **只读**各候选文件的**结论部分**（七环节表、六项经济指标、配对指标）
- **不看**你搜集过程中的推理、不看被淘汰候选的理由、不看你当时觉得哪条有戏
- **先写 rubric（六维权重），再打分。** 不许打完分再倒推权重来让心仪的那条胜出

---

## Step 1 · 六维加权打分卡

先写下权重并说明理由，再填分。每维 1–5 分。

| 维度 | 权重 | 打分依据（必须指向 research/ 里的具体数字） |
| --- | --- | --- |
| **变现速度** | 30% | time-to-first-dollar（天）。越短越高 |
| **无人托管度** | 25% | 人工小时/月。越低越高。> 4 h/月 一律 ≤ 2 分 |
| **冷启动可行性** | 15% | 冷启动成本占 ¥5k/$700 的比例；一次性人工设置总量 |
| **收入天花板** | 10% | 单位毛利 × 现实单量上限 |
| **抗衰减** | 10% | 收入衰减半衰期；被抄袭/被平台改规则打死的难度 |
| **合规与封号风险** | 10% | 封号率、退款争议率、ToS 明确性（**反向指标**） |

```markdown
| 候选 | 变现速度(30%) | 无人托管(25%) | 冷启动(15%) | 天花板(10%) | 抗衰减(10%) | 合规风险(10%) | 加权总分 |
|------|--------------|--------------|------------|------------|------------|--------------|---------|
```

**硬规则**：
- **打分卡必须给每一条进入深挖池的候选一行（6–8 行），不是只给 top 3。**
  用户有权推翻你的排名去选第 4 名——**你的工作是让他看得见全部排名，不是替他把选项藏起来。**
- 打分卡里**每个数字都要能在 `research/` 对应文件里找到出处**。找不到的格子填 `—` 并说明
- **有任何一维的依据是「未查到」的候选，不能进 top 3**——
  证据不足不等于分数中等，`REFERENCE §3.4`：高风险场景 fail-closed
- 权重可以调，但**必须在看分数之前调完并写下理由**

## Step 2 · 对抗性复核（反从众闸门）

对 **top 3 逐条**做一次，`REFERENCE §5.3`：

> Prompt 自己：**「试图反驳这条路径可行。不确定时默认判为已反驳。」**

每条至少从三个**不同镜头**攻击（不要三个一样的怀疑者）：

| 镜头 | 攻击什么 |
| --- | --- |
| **收款与合规** | 个人主体真的能开户吗？KYC 会不会卡住？两个法域都行吗？ |
| **需求真实性** | 付费方真的存在吗，还是只有 C 级来源在声称？谁的预算从哪个口子出？ |
| **衰减与竞争** | 这条路 6 个月后还在吗？入场门槛低到什么程度？平台改一次规则会不会归零？ |

复核结论写进备忘录，**包括没被反驳倒的理由**。
被三个镜头中的两个及以上反驳倒的候选 → 出局，从 top 3 里替换。

## 完成判据

- [ ] 选定**恰好一条**路径（不是「A 或 B 都行」）
- [ ] 第 2 节对两条落选候选各给出**具体判据**级的淘汰理由
- [ ] 打分卡**覆盖全部深挖候选（6–8 行）**，每格有值或 `—`+说明，每个数字能反查到 `research/`
- [ ] top 3 各有三镜头对抗性复核结论
- [ ] **第 4.5 节翻案条件表覆盖全部深挖候选**，每条的「什么必须为真」都是可操作的具体判据
- [ ] 30 天方案每一步有**可机器判定**的完成判据
- [ ] kill 判据表含**优化 / 反向 / 锚定**三类指标，不是只有优化指标
- [ ] 敞口自述非空（**声称没有敞口 = 没想清楚**）
- [ ] 七题逐条作答

## 失败处理

| 情况 | 怎么办 |
| --- | --- |
| top 3 都被对抗性复核反驳倒 | **这是合格结论**。写「本轮无合格路径」+ 三条各死在哪 + 需要什么信息才能翻案。**不许硬推一条出来** |
| 两条候选加权分接近（差 < 0.3） | 不要靠调权重分胜负。用**反向指标**破平（选封号/退款/衰减风险更低的），并写明用了破平规则 |
| 关键维度证据不足 | 该候选**不能进 top 3**（fail-closed）。写入敞口自述 + `OPEN-QUESTIONS.md` |
| 撞到闸门上限还没收口 | 用现有材料出备忘录，在敞口自述里**逐条写明哪些证据不足** |

## 安全边界

- 备忘录是**给人拍板的输入，不是执行授权**（`REFERENCE §2.4`：证据穿过边界，决策不穿过边界）。
  写完就停，**不要开始执行 30 天方案的任何一步**。
- 30 天方案里**不得包含**触碰 CLAUDE.md §2.4 红线的动作。
- **不得为了让结论好看而省略敞口自述。** 没有敞口自述的备忘录一律判未完成。
- 用全局 skill `no-ai-slop` 过一遍定稿：去掉「赋能」「闭环」「生态」这类空词，
  每一句要么是数字，要么是判断 + 依据。
