# 证据台账与来源分级

## 为什么这个任务特别需要它

搜索「怎么用 AI 赚钱」，首页结果里绝大多数是**内容营销**：
写这些文章的人靠**卖课、导流、联盟链接**赚钱，
「我月入 X 万」的截图是他们的**产品**，不是他们的**数据**。

这类内容有三个特征，识别出来就淘汰：

1. **数字总是漂亮的整数**，且从不给出成本侧
2. **不给可验证的一手凭证**（后台截图可以 P，且截图不是一手来源）
3. **文末必有转化动作**（加微信、进群、买课、注册链接）

> **默认判定：任何收入声明都不可信，除非有 A 级交叉验证。**

---

## 三级分法

| 级别 | 是什么 | 能用来做什么 |
| --- | --- | --- |
| **A · 一手** | 平台官方费率页 / 服务条款 / 开发者协议原文、上市公司财报与招股书、官方 API 文档、政府法规与官方公告、平台官方发布的统计 | **可直接作为结论依据** |
| **B · 二手** | 有署名的行业报告、正经媒体报道、学术论文、有署名的技术博客 | 可作佐证，**必须标注为待验证** |
| **C · 内容营销** | 「我用 AI 月入 X 万」、卖课落地页、无署名聚合站、SEO 农场、社媒截图、AI 生成的清单文 | **仅作为「存在这种玩法」的线索**，**绝不可作为数字依据** |

### 分级判定的四问

拿不准是 B 还是 C 时，问：

1. **谁写的？** 有署名和可核实的机构/身份 → 倾向 B；匿名或站名即公司名 → 倾向 C
2. **他靠什么赚钱？** 靠这篇文章导流转化 → C
3. **有没有给出成本侧和失败案例？** 只有收入没有成本 → C
4. **数字能不能被独立验证？** 不能 → 最高只能是 B，且必须标「待验证」

**拿不准就往低了判。**（`REFERENCE §8.3`：UNKNOWN 按最严格情况处理。）

---

## 三条硬规则

### 规则 1 · 关键事实只接受 A 级

以下**必须**有 A 级来源，否则写「未查到」：

- 费率、分成比例、抽成
- 提现门槛、结算周期
- KYC / 实名 / 资质要求
- ToS 中关于自动化、AI 生成内容、账号数量的条款
- 法规与税务要求

`REFERENCE §3.2`：**这些都是 L1 确定性检查能覆盖的东西**
（去官方页面看原文就有确定答案）。**用模型猜一个 = 用 L3 干 L1 的活 = 设计错误。**

### 规则 2 · 收入声明默认不可信

正确写法：

> 有 C 级来源声称此类路径月收入约 X（[来源](URL) · 2026-08-20 · C）。
> **未找到 A 级验证。** 可验证的是该平台的分成比例为 Y%（[官方费率页](URL) · 2026-08-20 · A）。

错误写法：

> ~~此类路径月收入约 X。~~ ←（没有来源、没有分级、把 C 级当事实）

### 规则 3 · 冲突记录，不择一

两个来源打架时，**两条都记，标注 CONFLICT**，并说明你倾向哪个及理由。

**冲突本身是重要发现**——同一个费率两处不一致，通常意味着
「有隐藏条件」「近期改过」「分地区/分档位」。这比一个干净的数字有信息量。

## 台账格式（`state/evidence-ledger.md`）

**append-only。已写入的行永不修改。** 发现旧条目有误 → **追加一条更正**，
引用原条目 ID，不要改原行。（`REFERENCE §8.1`：审计表 append-only，
应用层永不 UPDATE / DELETE。）

```markdown
# Evidence Ledger （append-only）

| ID | 抓取日期 | 级别 | 主张 | 数值/条款 | 来源 | 用于哪条候选 | 备注 |
|----|---------|------|------|----------|------|-------------|------|
| E001 | 2026-08-20 | A | 平台 X 对个人开发者的分成比例 | 70/30 | [官方费率页](URL) | #3, #7 | |
| E002 | 2026-08-20 | C | 某玩法月入声明 | ¥50k | [文章](URL) | #3 | 卖课页，仅作线索 |
| E003 | 2026-08-20 | A | 平台 X 结算周期 | T+45 | [官方帮助](URL) | #3 | **与 E00x 冲突** |
| E004 | 2026-08-20 | — | **更正 E001** | 65/35（2026-06 起） | [官方公告](URL) | #3, #7 | E001 引用的是旧版页面 |
```

### 每条必填五项

1. **抓取日期**（不是发布日期；页面会变）
2. **级别** A / B / C
3. **主张**（这条来源支持的具体命题，一句话）
4. **来源**（可点击 URL；打不开的注明「已失效，标题：XXX」）
5. **用于哪条候选**（便于反查：某条结论一旦被推翻，能立刻找到受影响的候选）

---

## 写入时机

**每次检索/抓取后立刻写。** 不许攒到最后统一整理
（CLAUDE.md §6 写作协议：Search → Edit → Search → Edit）。

攒到最后的必然结果：URL 记错、日期靠回忆、级别靠印象——台账失去全部价值。

---

## 完成判据

- `state/evidence-ledger.md` 中 **A 级来源 ≥ 15 条**（CLAUDE.md §11）
- 每条进入深挖池的候选，**至少 2 条 A 级来源**支撑其收款轨道与 ToS 结论
- 所有 CONFLICT 条目都有倾向性判断 + 理由
- 所有更正条目都引用了被更正的 ID

---

## 失败处理

| 情况 | 怎么办 |
| --- | --- |
| 官方页面 403 / 需登录 | 先写盘已有内容 → 试官方帮助中心 / 开发者文档 / 网页归档 → 三次拿不到则记「未查到」 |
| 只找到 C 级来源 | 记为 C，主张写成「有声称…，未验证」，**不许升格** |
| 官方页面改版，数字变了 | **追加更正条目**，引用原 ID。不要改原行 |
| 分不清 B 还是 C | 判 C（往低了判） |
| 找不到任何来源 | 写「未查到」+ 记入 `OPEN-QUESTIONS.md`。**绝不填一个看起来合理的数** |

## 安全边界

- **只读取公开信息。** 不注册账号、不登录、不提交表单、不绕过付费墙或登录墙。
- **不得为了凑够 A 级条数而升格来源等级。** 分级口径是冻结节点（CLAUDE.md §2）。
- **不得修改或删除已写入的台账行。** append-only 是这份台账唯一的价值来源。
- 台账里不写任何密钥、cookie、个人身份信息。
