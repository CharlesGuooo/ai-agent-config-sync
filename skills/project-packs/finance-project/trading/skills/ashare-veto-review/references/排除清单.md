# 理由码登记表

**每个码要什么证据才能触发。** 拿不到该证据就不能用这个码——改进 `not_checked[]`。

保持这份表薄。**臃肿的校验者会开始推理，而不是检查。**

## 第 1 层 · 硬标记（读代码结果）

| 理由码 | 触发条件 | 需要的证据 |
|---|---|---|
| `EXHAUSTED` | `SPEC-EXH-01` 命中（末强 ≥ 2 项） | 代码给出的命中项与各项字段值 |
| `REAL_DISTRIBUTION` | `SPEC-EXH-06` 命中（近跌停/一字跌停） | `change_pct` 值 + `high==low` 判定 |
| `NOT_STRONG` | `SPEC-EXH-04` 命中（该强不强） | 次日 `close < open` 且 `close < prev_close` |
| `GATE_CLOSED` | `SPEC-ENV-01`：`state ∈ {weak, lean_weak}` | `regime_history` 当日 `state` |
| `WRONG_REGIME` | `SPEC-ENV-05` 三种不宜操作情形之一 | 对应识别式的字段值 |

**规则未由代码执行时不得使用这些码**——写进 `not_checked[]`。

## 适用目标：哪个码只能用在哪一类上

**先看这张表再选码。** 2026-09-22 复盘六天实跑：45 条被代码否掉的排除里，
**35 条（78%）是把只对市场级成立的码套到了个股候选上**——`NO_BASE_RATE` 25 次、
`UNPARSEABLE_INVALIDATION` 10 次。这些码的校验器对个股根本不产生，所以**必然被拒**，
等于白写一条排除。

| 只能用在 `target: market` | 只能用在个股 `target: <代码>` | 两边都能用 |
| --- | --- | --- |
| `NO_BASE_RATE` | `DOMAIN_MISMATCH` | `PATTERN_NOT_FIRED` |
| `UNPARSEABLE_INVALIDATION` | | `STATE_CLASS_AS_EVIDENCE` |
| `OVERCONFIDENT` | | `QUOTA_EXCEEDED` |
| `INCONSISTENT_PROMO_RATE` | | `OUT_OF_LAYER` |

为什么：`base_rate`、`invalidation_condition`、`confidence` 这些字段**只有市场级判断有**。
个股候选的契约里没有它们，所以「该候选缺 base_rate」不是缺陷，是它本来就不要求。
个股候选要看的是 `sector` / `role` / `attribution_level` / `pattern_ids`。

语义码（`WEAK_DISCONFIRMATION`、`BROKEN_EVIDENCE`、`ATTRIBUTION_OVERREACH`）不走代码核验，
直接采纳，不受此表限制。

## 第 2 层 · 推理缺陷（本层今天最有产出）

| 理由码 | 触发条件 |
|---|---|
| `PATTERN_NOT_FIRED` | `pattern_ids` ⊄ 当晚确定性命中集合。**优先级最高** |
| `UNPARSEABLE_INVALIDATION` | `invalidation_condition` 无法对 `METRICS` / `regime_history` 列名解析，或次日无法用代码判真假 |
| `NO_BASE_RATE` | `base_rate` 缺失、为 null，或落在样本 < 12 的阶段（`ebb`/`ice`） |
| `WEAK_DISCONFIRMATION` | `disconfirming_evidence` 为空，或未引用具体的、与结论相反的字段值 |
| `OVERCONFIDENT` | `node_edge < 0` 而 `confidence > low` |
| ~~`DEAD_METRIC`~~ | **已退役（2026-09-06 P0 修复 `median_pct` 的 eps 尺度，七项指标皆可评分）。** 调度器对该码的排除一律标"拒绝"；不要再用 |
| `BROKEN_EVIDENCE` | 引用的字段值与数据对不上，或引用了平台没有的字段 |
| `ATTRIBUTION_OVERREACH` | 推测级归因被当作事实使用，或描述主力意图而非量价事实 |
| `STATE_CLASS_AS_EVIDENCE` | 引用了 `kind = 状态类` 的规则（命中 > 10%）来支撑方向性判断。见下 |
| `DOMAIN_MISMATCH` | 市场级规则（`SPEC-ENV-*`）出现在候选的 `pattern_ids` 里。**反方向允许**：市场级判断引用个股规则的全市场命中（如 `SPEC-EXH-01` 全市场仅 1 只）是合法的市场证据，SKILL.md 的示例即如此 |
| `QUOTA_EXCEEDED` | 单个标的引用**形态类**规则 > 2 个。**状态类不计入配额**（规格 §18），所以先剔除状态类再数 |
| `OUT_OF_LAYER` | 输出越层：给出仓位、加减仓比例、目标价、买卖动作。仓位由 `SPEC-RISK-01` 的公式算，不由研判层拍 |

### `STATE_CLASS_AS_EVIDENCE`：§18 在校验器侧的落地

规格 §18 实测：形态类规则命中率全在 2% 以下，状态类全在 19% 以上。
`SPEC-MA-04` 多头排列命中 37.6%、`SPEC-MA-01:支撑` 命中 50.6%——**半个市场都满足的条件是背景，不是形态**。

**为什么必须单独立码**：`PATTERN_NOT_FIRED` 只管命中/未命中，`QUOTA_EXCEEDED` 只管条数。
一条「命中了、但它是背景」的引用会从这两个码之间干净地漏过去——引用数是 1，不触发配额；
规则确实命中，不触发白名单。**§18 花整节写的规则，在校验器侧就不存在。**

**判定所需证据**：`hits.json` 的 `kind` 字段。

> **`kind` 字段缺失时，不要用规格 §18 的表反推然后照常判。**
> 写进 `not_checked[]`：「`hits.json` 无 `kind`，本轮未做状态类检查」。
> 反推能对上是运气（同一次运行），对不上会**静默少查一层且不报错**。

### `BROKEN_EVIDENCE` 的常见编造项

计划里出现这些**一律触发**——平台没有这些数据：

- 资金流 / 主力净流入 / 北向（G8）
- 涨停原因 / 政策名称（G6；龙虎榜 `limit_reason` 实测不返回）
- 封单量 / 封流比 / 首末封板时间 / 炸板次数（G3）
- 分时行为：站上分时均价线、10:30 前翻红、盘中开合次数（G1）
- 集合竞价量比 / 竞价过程（G4）
- 热度榜排名 / 人气排名（G5）

**计划用降级判据并明确标注了降级，不触发本码**（那是正确做法）。
**未标注就直接陈述这些事实，触发。**

### 常见但不触发的情况

- 输出 `无判断` —— 这是一等结果，不是缺陷
- `repair` 日无市场级判断 —— 实测该阶段占 84.8%，本就该多数沉默
- 归因写「无法归因」 —— 无新闻源时的正确输出
