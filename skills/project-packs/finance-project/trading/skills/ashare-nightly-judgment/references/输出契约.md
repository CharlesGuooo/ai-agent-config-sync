## 指标菜单与 eps 死区

`direction(cur, prev, eps)` 的判定是：`abs(cur - prev) <= eps` → `持平`，否则按符号取 `上升`/`下降`。
**不做任何量纲缩放。** 所以 eps 必须与落盘值的标度匹配——有一项不匹配：

| metric | 中文 | eps | 落盘标度 | 日变化中位数 | 实测方向分布（上升/下降/持平） |
|---|---|---:|---|---:|---|
| `limit_up` | 涨停家数 | 5.0 | 计数 | 16 | 92 / 98 / 53 |
| `max_consecutive` | 最高连板高度 | 0.5 | 计数 | 1 | 140 / 67 / 36 |
| `strong_down_pct` | 大跌家数占比 | 2.0 | 0–100 | 6.83 | 105 / 89 / 49 |
| `seal_rate` | 封板率 | 0.05 | 0–1 | 0.077 | 77 / 78 / 88 |
| `promo_rate` | 晋级率 | 0.05 | 0–1 | 0.051 | 65 / 60 / 116 |
| `ge2_count` | 二板以上家数 | 3.0 | 计数 | 3 | 59 / 59 / 125 |
| `median_pct` | 全市场中位涨幅 | 0.005 | 小数（−0.06 ~ 0.04） | 0.0118 | 待重测（修复前为 0 / 0 / 243） |

**`median_pct` 自 2026-09-06（P0）起可用**：eps 由 0.5 改为 0.005，与小数落盘值同尺度；
`tests/test_scoreboard.py` 里有一条守卫测试保证七个指标的 eps 都小于日变动的 p90，这类错配以后进不来。

**`promo_rate` / `ge2_count` / `seal_rate` 偏钝**：约一半的日子落在死区里。
预测它们「持平」是低信息量的安全牌——**记分牌照样算 edge，所以安全牌不会给你分数**。

## `invalidation_condition` 的可解析写法

要求：**能对 `METRICS` 的字段名与 `regime_history` 的列名解析**，且能用代码在次日判定真假。

可解析（✅）：

```
次日 seal_rate > 今日 且 ge2_count 上升
次日 limit_up < 20
次日 max_consecutive 未创新高
```

不可解析（❌，写成这样整条判断作废）：

```
如果市场情绪继续降温          ← 「情绪」不是字段
若资金流出加剧                ← 无资金流数据（G8）
明天没有更好的板块出现        ← 「更好」无定义
若龙头炸板                    ← 炸板是个股事件，不在 METRICS 菜单里
```

最后一条值得单独说：**个股级的失效条件写在 `candidates[].invalidation_condition` 里，
市场级的写在 `market.invalidation_condition` 里，两者不要混。** 只有市场级的进记分牌。

## `base_rate` 怎么取

`baseline_rates(rows, upto_idx, metric, horizon=1)` 回看 `BASELINE_WINDOW = 60` 天，
返回该 metric 各方向的历史发生率。

- **样本不足 `MIN_BASELINE_SAMPLES = 12` 时返回 `None`** → 此时输出 `无判断`，不要用直觉填一个数
- 取的是**你即将预测的那个方向**的基准率，不是全部方向的

## 一个完整例子

```yaml
market:
  metric: seal_rate
  direction: 上升
  base_rate: 0.3833            # baseline_rates(..., "seal_rate", horizon=1)["上升"]，n=60
  confidence: low
  pattern_ids: [SPEC-EXH-01, SPEC-EXH-06]
  evidence_dates: [2026-09-04]
  evidence:
    - "phase=repair，state=lean_weak，SPEC-ENV-01 闸门关闭"
    - "seal_rate=0.3333 == 60 日窗口最小值；eps=0.05 意味着判「下降」需再创新低 5 个百分点"
    - "SPEC-EXH-01 全市场仅命中 1 只（605577.SH，5 连板），市场高度集中在一只被判为末强的独苗上"
  disconfirming_evidence: "broken_limit=66 处 60 日 94.2 分位 —— 封板率崩塌是主动砸盘的结果，
    卖压主体仍在；score 连续三日 37→35→30，无一处显示企稳"
  invalidation_condition: "次日 seal_rate <= 0.3833"
node_edge: -0.134
```

读法：基准率 38.3% 的情况下预测「上升」，**主张的不是「会上升」，而是「比 38.3% 更可能上升」**。
`confidence` 锁在 `low`，因为 `node_edge` 为负。反证据写的是真正反面的事实，不是敷衍。

> **这个例子刻意不用 `promo_rate`。** 2026-09-04 那一行 `promo_rate(0.0667) × promo_pool(45) = 3.00`
> 而 `ge2_count = 7`——244 行里唯一不满足该恒等式的一行，恰好就是这天。
> **用 `promo_rate` 前先验这个恒等式**，`spec_rules.py` 会自动报。

## 记分牌怎么判你

```
edge = 命中(1/0) − 该方向过去 60 日的基准发生率
```

- `edge ≈ 0` → 你判的是本来就会发生的事
- `edge < 0` → 不如按历史常态猜
- 验收线：`mean(edge) > 0`，且有基准的样本数 ≥ 12

**当前基线是 `PHASE_EXPECTATIONS` 那张手写表的 `mean(edge) = −0.134 (n=80)`。**
本节点上线的唯一门槛是跑赢它。

> 注意：`scoreboard.py` 今天评的是那张确定性表，**不评 LLM 输出**。评 LLM 是 O9(b)，尚未实现。
> 在评分接口到位之前，本 skill 的输出只能做结构性校验（字段齐全、可解析、白名单合规），**拿不到 edge**。
